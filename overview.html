flask_Practice · CI/CD Assignment

A working CI/CD pipeline from git push to a live container on EC2 — with test, build, ECR push, deploy, health check, and SNS notification.

Python 3.12 Flask MongoDB Atlas Docker GitHub Actions AWS ECR AWS EC2 AWS SSM Ansible Terraform Amazon SNS

What this is

Forked from mohanDevOps-arch/flask_Practice. A small Flask + MongoDB "student registration" app becomes the vehicle for a real CI/CD pipeline:

  • Every push to main runs pytest, builds a Docker image tagged with the commit SHA, pushes to ECR, and deploys onto EC2.
  • Deployment happens over SSM (no SSH, no port 22) using the built-in AWS-ApplyAnsiblePlaybooks document — SSM pulls this repo onto the instance and runs an Ansible playbook there.
  • Runtime secrets live in SSM Parameter Store as SecureString and are fetched on the instance, never transiting the CI runner.
  • A /health endpoint is the real deploy gate — the pipeline only reports success if it returns 200 {"status":"healthy"}.
  • Success/failure notifications go through an SNS topic with tailored subject + body.

Pipeline stages

CheckoutLatest source on push to main.
Installpip install -r requirements.txt.
Testpytest against a Mongo service container. Fails the build.
Builddocker build, tagged with the commit SHA.
Push ECRAuthenticated ECR push (SHA tag + latest).
DeploySSM ↦ Ansible playbook on the tagged EC2. Idempotent.
VerifyExternal curl /health retries with hard fail.
NotifySNS publish. Failure email names the failed stage.

Getting started

  1. Fork & clone — gh repo fork mohanDevOps-arch/flask_Practice --clone.
  2. Provision AWS — 
    cd infra/terraform
cp terraform.tfvars.example terraform.tfvars   # fill mongo_uri, secret_key, notify_emails
terraform init && terraform apply
  3. Push outputs into GitHub secrets — copy the gh secret set … block from infra/terraform/README.md.
  4. Confirm the SNS email — AWS sends a one-time "Confirm subscription" link to each address in notify_emails.
  5. Push a change — the pipeline runs on main, deploys the image, and emails the outcome.
  6. Test the failure path — break a test intentionally to receive a failure email with the correct stage name.

Trade-offs called out

Static access keys, not OIDC

Simpler setup; the GHA secret access key lives in Terraform state. Rotate with terraform apply -replace=aws_iam_access_key.gha.

Single EC2, no load balancer

Matches the assignment brief. Deploy has a brief moment of downtime during docker stop → run.

Runtime secrets in Parameter Store

MONGO_URI / SECRET_KEY never touch the CI runner or CloudTrail command params. Ansible fetches them on the target.

Local Terraform state

Fine for a lab. Move to S3 + DynamoDB lock for team use.
